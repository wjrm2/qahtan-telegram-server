# حزمة عز — بوت Telegram مستقل

تحتوي هذه الحزمة على بوت Telegram بلغة Python فقط. تم فصل الموقع والواجهة الجديدة عنها؛ مشروع الموقع محفوظ بشكل مستقل في مستودع `az-glass-dashboard` ولا يبدأه البوت ولا يعتمد عليه في التشغيل.

## الملفات

| الملف | الوظيفة |
|---|---|
| `bot.py` | بوت Telegram مع الذكاء الاصطناعي والذاكرة والكتالوج النصي |
| `run_all.py` | مشغل بوت Python فقط |
| `requirements.txt` | اعتماديات Python |
| `.env.example` | نموذج الإعدادات السرية والمنافذ |

## التشغيل المحلي

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run_all.py
```

بعد التشغيل:

- بوت Telegram يعمل عبر polling.
- فحص Flask متاح على `http://127.0.0.1:8080/health`.
- لا يبدأ البوت أي خادم Node أو واجهة موقع.

## متغيرات البيئة المهمة

يجب تعبئة `BOT_TOKEN` و`GROQ_API_KEY` و`DEVELOPER_IDS` و`DEVELOPER_MODE_CODE`. ويمكن وضع `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` فقط إذا كانت ميزات الإشعارات الاختيارية مطلوبة. يمكن أن تكون قيمة `TELEGRAM_BOT_TOKEN` نفسها قيمة `BOT_TOKEN`، لكن أبقيت المتغيرين منفصلين حتى تستطيع تغيير أحدهما لاحقًا.

استخدم `BOT_PORT` لمنفذ Flask. في بيئات الاستضافة التي تعطي متغير `PORT` تلقائيًا، اجعل Flask يستخدم `PORT` أو عدّل `BOT_PORT` وفق إعداد المنصة.

## التحسينات المضافة

أزيل مفتاح Groq المضمّن من الكود، وأصبح رمز المطور ومعرّفات المطورين ومتغيرات الاتصال إعدادات بيئية. أضيفت ذاكرة محادثة مؤقتة محدودة، وتحسنت معالجة أخطاء المزودات والاتصالات الشبكية. يعمل `run_all.py` على تشغيل البوت فقط، ولا توجد واجهة موقع أو خادم Node ضمن دورة التشغيل.

## التشغيل من GitHub

أضفت ملف `.github/workflows/run-bot.yml` للتشغيل اليدوي عبر GitHub Actions. بعد رفع المشروع، أضف القيم السرية من تبويب `Settings > Secrets and variables > Actions` ثم شغّل workflow باسم `Run Qahtan bot` من تبويب `Actions`. هذا التشغيل مؤقت؛ GitHub Actions ليس سيرفرًا دائمًا، وقد تتوقف المهمة عند انتهاء مدة التشغيل أو عند انتهاء الحصة المجانية. للتشغيل 24/7 استخدم VPS أو خدمة استضافة دائمة، واجعل GitHub مستودع الكود فقط.

## الميزات المضافة

أضيفت وحدة `features.py` وتحتوي على تنزيل روابط TikTok العامة بحد أقصى قابل للضبط، وتلوين أزرار `InlineKeyboardButton` داخل ملفات Python نصيًا دون تشغيل الملف، وربط القنوات العامة التي يكون المستخدم والبوت مشرفين فيها، ونشر نصوص بسيطة مع إحصائيات SQLite. الأوامر الجديدة هي `/features` و`/tiktok` و`/colorbuttons` و`/linkchannel` و`/channels` و`/publish` و`/featurestats`. كما أضيفت أدوات عامة مستقلة: `/commands` و`/qr` لإنشاء QR، و`/checkurl` لفحص رابط، و`/remind` للتذكيرات المؤقتة، و`/cancelreminders` لإلغائها، و`/compress` لضغط الصور، و`/id` للمعرفات، و`/ping` لقياس الاستجابة، و`/privacy` لشرح سياسة الخصوصية.

لم أدمج وظائف سكربت TikTok التي تطلب `sessionid` أو تنفذ إلغاء متابعة جماعيًا أو حذف فيديوهات أو حظر مستخدمين أو تغيير بيانات الحساب؛ هذه عمليات حساسة ومدمرة وتحتاج مراجعة مستقلة وصلاحيات صريحة. كذلك لا يشغّل تلوين الأزرار أي كود مرفوع من المستخدم.

## لوحة تحكم السيرفر داخل Telegram

تظهر لوحة **تحكم بالسيرفر** داخل لوحة المطور فقط بعد إدخال رمز المطور `505`. تحتوي على قراءة حالة النظام والقرص ووقت التشغيل، عرض آخر السجلات المتاحة، عرض قائمة ملفات المشروع المسموحة، وزر **كمبيوتر آمن** يعرض معلومات Python وLinux وتشخيصًا ثابتًا. كما يمكن إيقاف البوت بعد تأكيد مزدوج. لا توجد ترمنال مفتوحة ولا تنفيذ أوامر يرسلها المستخدم؛ هذا مقصود لحماية السيرفر من تنفيذ أوامر عشوائية عبر Telegram.

## ملاحظات أمنية

لا تضع قيم `.env` داخل GitHub ولا ترسلها إلى أي شخص. يجب تغيير رمز المطور القديم وتدوير أي Bot Token أو Groq API Key سبق نشره في ملفات أو محادثات. يقتصر تشغيل البوت على أوامر Telegram المصرح بها ولا يفتح منفذ تنفيذ أوامر عامة من واجهة موقع.

## كتالوج الخدمات النصي

أضيف `service_catalog.py` كطبقة كتالوج مستقلة تضم 140 خدمة موزعة على 14 تصنيفًا. كل زر يعرض اسم الخدمة، نوع المصادقة، المتطلبات، وحالة التفعيل. وجود الخدمة في الكتالوج لا يعني منحها صلاحية تلقائية؛ الربط الفعلي يحتاج إعداد OAuth أو مفتاح API محفوظًا خارج Git، مع مبدأ أقل الصلاحيات وتأكيد العمليات الحساسة.

أضيفت صورة الرأس `assets/qahtan_header.gif` إلى رسالة `/start`، وأعيد ترتيب الأزرار إلى محادثة مستمرة، كتالوج الخدمات، الميزات، التخصيص، الإحصائيات، والمساعدة. لا يحتوي مسار `/start` على زر WebApp أو رابط إلى الموقع.

## DeepSeek والذاكرة

يمكن اختيار DeepSeek كمزود الذكاء الافتراضي عبر `AI_PROVIDER=deepseek` و`DEEPSEEK_API_KEY` و`DEEPSEEK_MODEL`. يستخدم البوت واجهة DeepSeek المتوافقة مع OpenAI، ويحتفظ بمسار fallback إلى Groq عند فشل المزود الأساسي. لا تضع أي مفتاح في GitHub أو داخل الكود؛ استخدم أسرار المنصة أو ملف `.env` غير المتعقب.

تتضمن رسالة النظام سياق Qahtan، والكتالوج، ومتطلبات التأكيد، والعزل الخاص بتشغيل Python. هذا السياق لا يمنح النموذج تنفيذًا مباشرًا؛ أي تنفيذ يجب أن يمر عبر عامل معزول ومتحقق من الصلاحيات.
