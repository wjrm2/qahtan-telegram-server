# حزمة Qahtan المدمجة مع خادم الاستضافة

تحتوي هذه الحزمة على بوت Telegram بلغة Python وخادم Node/Express في مجلد واحد. يعمل `run_all.py` على تشغيل الخادمين معًا، بحيث يبقى البوت مسؤولًا عن Telegram والذكاء الاصطناعي، بينما يبقى خادم Node مسؤولًا عن واجهة التطبيق ومسارات التنفيذ وإرسال الملفات.

## الملفات

| الملف | الوظيفة |
|---|---|
| `bot.py` | بوت Telegram المحسن مع الذكاء الاصطناعي والذاكرة المؤقتة وأمر فحص الخادم |
| `run_all.py` | مشغل الخادمين معًا وإيقاف Node تلقائيًا عند توقف البوت |
| `requirements.txt` | اعتماديات Python |
| `node_server/server.ts` | خادم Node/Express المدمج |
| `node_server/package.json` | اعتماديات وأمر تشغيل Node |
| `.env.example` | نموذج الإعدادات السرية والمنافذ |

## التشغيل المحلي

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
cd node_server
npm install
cd ..
python run_all.py
```

بعد التشغيل:

- بوت Telegram يعمل عبر polling.
- فحص Flask متاح على `http://127.0.0.1:8080/health`.
- فحص Node متاح على `http://127.0.0.1:3000/api/health`.
- المطور يستطيع استخدام الأمر `/server` داخل البوت لفحص اتصال البوت بخادم Node.

## متغيرات البيئة المهمة

يجب تعبئة `BOT_TOKEN` و`GROQ_API_KEY` و`DEVELOPER_IDS` و`DEVELOPER_MODE_CODE`. كما يجب وضع `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` إذا كان خادم Node سيرسل إشعارات الملفات إلى Telegram. يمكن أن تكون قيمة `TELEGRAM_BOT_TOKEN` نفسها قيمة `BOT_TOKEN`، لكن أبقيت المتغيرين منفصلين حتى تستطيع تغيير أحدهما لاحقًا.

استخدم `BOT_PORT` لمنفذ Flask و`NODE_SERVER_PORT` لمنفذ Node. لا تستخدم المنفذ نفسه للخادمين. في بيئات الاستضافة التي تعطي متغير `PORT` تلقائيًا، اجعل Flask يستخدم `PORT` أو عدّل `BOT_PORT` وفق إعداد المنصة، واجعل `NODE_SERVER_PORT` منفذًا داخليًا متاحًا للخادم.

## التحسينات المضافة

أزيل مفتاح Groq المضمّن من الكود، وأصبح رمز المطور ومعرّفات المطورين ومتغيرات الاتصال إعدادات بيئية. أضيفت ذاكرة محادثة مؤقتة محدودة، وتحسنت معالجة أخطاء Groq والاتصالات الشبكية. أضيف أمر `/server` للمطور لفحص خادم Node، كما أصبح تشغيل الخادمين وإيقافهما منظمًا عبر `run_all.py`. وتم إصلاح تشغيل ملف TypeScript باستخدام `tsx` بدل تشغيله مباشرة بواسطة Node.

## التشغيل من GitHub

أضفت ملف `.github/workflows/run-bot.yml` للتشغيل اليدوي عبر GitHub Actions. بعد رفع المشروع، أضف القيم السرية من تبويب `Settings > Secrets and variables > Actions` ثم شغّل workflow باسم `Run Qahtan bot` من تبويب `Actions`. هذا التشغيل مؤقت؛ GitHub Actions ليس سيرفرًا دائمًا، وقد تتوقف المهمة عند انتهاء مدة التشغيل أو عند انتهاء الحصة المجانية. للتشغيل 24/7 استخدم VPS أو خدمة استضافة دائمة، واجعل GitHub مستودع الكود فقط.

## الميزات المضافة

أضيفت وحدة `features.py` وتحتوي على تنزيل روابط TikTok العامة بحد أقصى قابل للضبط، وتلوين أزرار `InlineKeyboardButton` داخل ملفات Python نصيًا دون تشغيل الملف، وربط القنوات العامة التي يكون المستخدم والبوت مشرفين فيها، ونشر نصوص بسيطة مع إحصائيات SQLite. الأوامر الجديدة هي `/features` و`/tiktok` و`/colorbuttons` و`/linkchannel` و`/channels` و`/publish` و`/featurestats`. كما أضيفت أدوات عامة مستقلة: `/commands` و`/qr` لإنشاء QR، و`/checkurl` لفحص رابط، و`/remind` للتذكيرات المؤقتة، و`/cancelreminders` لإلغائها، و`/compress` لضغط الصور، و`/id` للمعرفات، و`/ping` لقياس الاستجابة، و`/privacy` لشرح سياسة الخصوصية.

لم أدمج وظائف سكربت TikTok التي تطلب `sessionid` أو تنفذ إلغاء متابعة جماعيًا أو حذف فيديوهات أو حظر مستخدمين أو تغيير بيانات الحساب؛ هذه عمليات حساسة ومدمرة وتحتاج مراجعة مستقلة وصلاحيات صريحة. كذلك لا يشغّل تلوين الأزرار أي كود مرفوع من المستخدم.

## لوحة تحكم السيرفر

تظهر لوحة **تحكم بالسيرفر** داخل لوحة المطور فقط بعد إدخال رمز المطور `505`. تحتوي على قراءة حالة النظام والقرص ووقت التشغيل، فحص خادم Node، عرض آخر السجلات المتاحة، عرض قائمة ملفات المشروع المسموحة، وزر **كمبيوتر آمن** يعرض معلومات Python وLinux وتشخيصًا ثابتًا. كما يمكن إيقاف البوت بعد تأكيد مزدوج. مسار السجل أصبح مطلقًا داخل المشروع حتى يعمل زر السجلات من GitHub Actions. لا توجد ترمنال مفتوحة ولا تنفيذ أوامر يرسلها المستخدم؛ هذا مقصود لحماية السيرفر من تنفيذ أوامر عشوائية عبر Telegram.

## ملاحظات أمنية

لا تضع قيم `.env` داخل GitHub ولا ترسلها إلى أي شخص. يجب تغيير رمز المطور القديم وتدوير أي Bot Token أو Groq API Key سبق نشره في ملفات أو محادثات. مسار `/api/execute` في خادم Node يشغّل كودًا مرفوعًا على النظام؛ لذلك لا تعرضه للعامة دون مصادقة وعزل حقيقي للعمليات وحدود للوقت والذاكرة.
